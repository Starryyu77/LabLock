# /lab-handoff

You are packaging context for an external AI. The goal: produce a single self-contained markdown file that an external AI (which has no access to the user's local files) can read and answer well.

The user typically arrives here when:

- They've hit a debugging wall and want a second opinion (`/lab-debug` Phase 6 → `/lab-handoff`)
- They want a method check or formalism review from a stronger model
- They want help writing a paper section
- They want design feedback

## Pre-flight

Required:

- `--type=<mode>`: `debug | method | results | design | writing`. If user didn't specify, ask which.
- `--topic=<short-name>`: used in the filename. Slugified.

Optional:

- `--exp=<exp-id>`: if the handoff is about a specific experiment. Auto-detected from `.lablock/state/current-exp` if not given.
- `--branch`: after writing, also push to `handoff/<date>-<topic>` branch and print URL.

## Common context (all modes)

Every handoff bundle starts with:

```markdown
# Handoff: <topic>

> Generated by LabLock <date>. Self-contained context for external AI consultation.

## Project background

**Project**: <name from PROJECT.md>
**Domain**: <one-line goal>
**Current formalism version**: <vN from formalism.md>

<2-3 sentences from PROJECT.md "Method" section>

## Current state

**Active experiment**: <exp-id> (<status>)
**Hypothesis**: <one-liner from hypothesis.md>
**Recent commits** (last 7 days):
- <hash> <message>
- ...
```

This frames the AI before mode-specific content.

## Step: Write the bundle

Save to:

```
handoffs/outgoing/<date>-<topic>.md
```

## Step: Optional GitHub branch

If `--branch`:

```bash
git checkout -b handoff/<date>-<topic>
git add handoffs/outgoing/<filename>
git commit -m "[main] handoff: <topic>"
git push -u origin handoff/<date>-<topic>
```

Then print the GitHub URL of the file:

```
https://github.com/<owner>/<repo>/blob/handoff/<date>-<topic>/handoffs/outgoing/<filename>
```

The user can paste this URL into an external AI's chat (Claude.ai web, ChatGPT) and the AI can fetch it directly. This is much cleaner than copy-paste.

Switch back:

```bash
git checkout <previous-branch>
```

## Step: Reminder about reply

Tell the user:

> Bundle saved. Paste it (or the URL) into your external AI of choice. When you have a reply, save it as `handoffs/incoming/<same-filename>` and run `/lab-handoff --reply` to process the response.
>
> If using GitHub URL: handoff branches are auto-archived after 7 days by `/lab-tidy`. If you want to keep this one longer, mention it in the relevant decision.

## Reply mode (`--reply`)

If user runs `/lab-handoff --reply` with a file in `handoffs/incoming/`:

1. Read the reply.
2. Classify: is this advice (suggestions to consider) or actionable (specific code/config)?
3. If actionable code: produce a patch plan, ask for user confirmation before applying.
4. If advice: summarize key suggestions and write a follow-up note in `decisions/` if any decisions were made.
5. **Never auto-apply suggested code**. The external AI doesn't have full context; verify before merging.

## Don't

- Don't paste images. Use text descriptions of plots (loss went from X to Y over N steps).
- Don't paste base64 or binary. If the AI needs to see something binary, that's not a handoff candidate.
- Don't include credentials or secrets. Scan the bundle for API keys, tokens before saving.
- Don't auto-apply replies from external AIs. They're advisory.
- Don't make handoff bundles longer than necessary. ≤ 5k tokens of context is much better than 20k.
